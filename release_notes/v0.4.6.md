# Kintsugi v0.4.6

The workspace-helper protobuf schema is embedded in JavaScript bundles. System can load its supervisor without looking for a missing `/opt/proto/workspace_helper.proto` file. This fixes the packaged boot defect found after v0.4.5 publication.

## Packaging and verification

- Import the schema as text and build the gRPC definition with the explicitly pinned protobufjs 7.6.2 dependency. Protocol names, encoding options, mutual TLS and namespace checks are unchanged.
- Add a regression check that relocates the helper bundle and imports it without its source tree or a separate proto file.
- Make the app-image smoke check import the actual helper module.
- Gate native AMD64 and ARM64 image publication on booting the packaged System supervisor and real app to healthy `/up`, with no source-checkout mount. The disposable fixture uses its own volume and bounded containers; it changes only the app's preload label to use preloaded test dependencies. No application code is replaced.

The previous native smoke checks established binary availability, assets and resource bootstrap; they did not establish supervisor entrypoint boot. The new paired-runtime check closes that gap.

Host terminals, credential grants, network restrictions, custom sources, explicit image pins and paired rollback are retained. No application environment variable is added. Compatibility counters and the Go 1.26.10 runtime pin are unchanged.

Adapted from upstream [7d140bb2](https://github.com/lucasmeijer/AgentsInTheCloud/commit/7d140bb2b01f8639bbd33b54bd479357c815de79). Lucas Meijer and Larry Hudson attribution and MIT notices remain intact.

Publication advances `latest` only. `stable` stays at v0.4.1. No existing installation is updated or restarted.
