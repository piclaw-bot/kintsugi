# v0.2.0

Kintsugi adds exact private TCP grants and GitHub-backed update notes, while preserving custom image sources, private registry access, version pins and retained-pair rollback.

## Listed hosts only

- Combine security-scoped global and template lists of exact `host:port` destinations. Saving a list grants nothing; choose **Listed hosts only**, then park and unpark the workspace.
- Resolve names through the workspace DNS view and pin permitted private addresses when applying the snapshot. Later DNS answers cannot widen access.
- Enforce IP/TCP-port tuples for native traffic and hostname/IP/port checks in the proxy. Protected destinations, management services and peer workspaces remain excluded. Off and existing CIDR modes retain their behaviour.
- Publish System capability 2 and app policy-reader format 2. The app minimum remains 0; selecting listed-host mode requires installation services at capability 2.
- Block incompatible managed downgrades while listed-host policies are desired or applied. Apply Off to every affected workspace before downgrading; image rollback does not restore settings.

## What’s new

- Show published GitHub releases crossed by the installed and selected app revisions, including non-semver release tags. Drafts, prereleases and unrelated commits are excluded.
- Support custom app repositories through the pinned image’s `org.opencontainers.image.source` GitHub URL. An optional `owner/name` override in What’s new applies to that view without changing saved image sources or pins.
- Read pinned metadata through System, including its private registry access. Private GitHub notes use the existing GitHub connection; registry credentials are never sent to GitHub.
- Refuse stale metadata, divergent histories and invalid repository inputs. Notes failures do not prevent downloading a compatible update.

## Mobile composer

- Align prompt-template buttons with the send slot on phones.
- Keep the captioned **Connect to send** action inside its slot, without changing Kintsugi’s smaller controls or manual divider resizing.
- Add an explicitly partial, no-inference composer acceptance mode for layout checks on a real app.

## Verification and limits

The local full suite passed 2,176 tests, with 39 skips and zero failures. Lint, types, System bundling and workflow validation passed. Disposable fixtures verified 60 IPv4/IPv6 packet-flow checks, live System DNS pinning, proxy hostname/port enforcement, failed-apply restoration and workspace DNS bootstrap/restart behaviour.

The six-scenario Chrome layout subset passed all 89 checks twice. Full sending/busy-agent and iOS soft-keyboard acceptance have not passed: the staged app needs a connected model, and the iOS tier also needs a remote simulator.

This release does not include the seven upstream commits added after `3a2e417a`. Tagged GitHub Actions verifies native AMD64/ARM64 images and the app/System pair before publishing versioned images and advancing `latest`. `stable` stays unchanged. Publication does not restart installations.
