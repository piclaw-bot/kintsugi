# v0.3.1

This patch incorporates seven reviewed upstream commits through `012730c6`, adds GitLab.com and Bitbucket Cloud connections, and fixes the generated Caddy configuration’s conflict with Tailscale UDP 41641.

## Changes view

- Show unchanged tracked files alongside changes, loading their contents on demand.
- Edit unchanged working-tree text files through the existing conflict-checked edit flow. Committed comparisons stay read-only.
- Preview images, including unchanged images, and play unchanged video and audio when the browser supports their formats.

## Git hosting

- Move GitHub behind a shared Git-hosting provider interface.
- Add GitLab.com token connections, public/member project search, HTTPS Git credentials, SSH host trust and the `glab` CLI.
- Add Bitbucket Cloud email/API-token connections, repository search across account workspaces, HTTPS Git credentials, SSH host trust and the `bkt` CLI.
- Keep real provider tokens outside workspace environments; workspaces receive host-scoped placeholders and the non-secret account fields required by provider CLIs.
- Keep existing GitHub token storage and disconnect markers compatible with older installations and authenticated release-note lookup.
- Preserve Kintsugi’s applied network policy, host exclusions, response scrubbing and disabled URL-query secret substitution.
- Reject Bitbucket pagination URLs outside its HTTPS API origin before forwarding credentials, and refuse Bitbucket API redirects.
- Keep repository search and provider connection forms excluded from the authenticated admin API. One provider’s search failure does not hide other providers’ results.

GitLab support targets gitlab.com; arbitrary self-hosted GitLab servers are not included. Existing workspace containers do not receive newly added CLI binaries or environment variables merely because the app was updated. They need preparation against the updated workspace image; custom images still need to supply their own tools.

## Caddy and Tailscale

Generated HTTPS proxy configuration now disables HTTP/3 specifically on each configured bind address at port 41641. The TCP preview origin remains available, Tailscale keeps UDP 41641, and other listeners retain their protocol defaults.

An app update does not rewrite an external Caddyfile. Regenerate or amend it as described in [the proxy recovery instructions](https://github.com/rcarmo/kintsugi/blob/v0.3.1/docs/automation.md). Merge generated `servers` options into an existing global options block instead of adding a second block. Keep unrelated sites, admin settings and other global options. Validate and confirm the reload succeeds.

The preview range remains `41000–41999`; existing and retired origins are preserved. The APT balancing proposal was not adopted; Kintsugi retains its semantic APT groups, with Git-provider CLI packages supplied by their modules.

## Verification and limits

The local full suite passed 2,254 tests, with 39 skips and zero failures. Frozen dependency installs, lint/types, System bundling and workflow validation passed. External dependency versions were not updated.

Manual review covered Git-hosting connection forms on desktop/mobile, unchanged-file editing with persisted disk changes, image previews, and WebM/WAV playback. This browser lacks H.264 support, so its MP4 fixture was unsupported. The six-scenario, no-inference Chrome composer subset passed all 89 checks; sending, busy states, long transcripts and iOS keyboard behaviour were outside that subset.

A disposable, network-isolated runtime probe started all 1,000 Caddy TCP preview listeners while another process held UDP 41641, and confirmed that neighbouring HTTP/3 UDP 41642 remained available. The generated full-pool configuration also passed Caddy validation.

The browser review used an existing released workspace image as a UI fixture. Native publication checks execute `gh`, `glab` and `bkt` on both architectures in the new workspace image. Real GitLab/Bitbucket account sign-in, private remote cloning, physical microphone prompts, iOS keyboard/rotation and a complete installed update/rollback cycle have not been verified for this release.

System capability and app policy-reader format remain 2; the app minimum remains 0. Custom release sources, pins, registry credentials and retained-pair rollback protections are unchanged. Publication advances `latest`, leaves `stable` unchanged and does not restart installations.
