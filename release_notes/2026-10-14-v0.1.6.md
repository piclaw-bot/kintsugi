# v0.1.6

This support release introduces an explicit app/installation compatibility contract. System advertises compatibility version 1; the app still requires version 0 so existing installations remain supported while the foundation rolls out.

- Stamp compatibility labels from the source checkout and report the running installation's version.
- Check immutable app/System targets during discovery, preparation, activation and retained-pair rollback.
- Refuse incompatible app-only updates before downloading. When an older metadata API cannot verify requirements, offer the matching installer command.
- Check the app minimum before loading persisted app state when it relies on a versioned installation.
- Verify both native architectures and candidate compatibility before publication. Advance System before the app.
- Preserve saved repositories, private registry access, explicit pins and the existing stored update-plan format.

The full local suite and a manually dispatched CI checkpoint passed 2,113 tests with 39 skips and zero failures. Lint, TypeScript and workflow validation passed. Installer guidance was reviewed manually using the actual manager and renderer with sample versions.

This release does not add exact-host network grants or raise the app's minimum compatibility version. Those are subsequent convergence work. The compatibility counters use Kintsugi's own namespaced contract and do not claim upstream's separate private-network operations.

Tagged publication verifies the native AMD64/ARM64 images before publishing versioned app, System and workspace images and advancing `latest`. `stable` is unchanged. Publication does not restart existing installations.
