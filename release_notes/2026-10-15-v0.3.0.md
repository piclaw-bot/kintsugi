# v0.3.0

This minor release adds built-in agent code mode, subscription usage improvements and more preview capacity. It incorporates reviewed upstream changes through `97e32dea` and selected contributions from Larry Hudson’s fork.

## Improvements and fixes

- Let built-in agents run code-mode scripts, with classifier and image models and nested tool results.
- Keep stopped turns separate and report what stopped scripts completed or cancelled.
- Validate classifier-only provider credentials without requiring a chat model, including TypeSafe credential bridging into Pi.
- Show OpenCode Go five-hour and weekly usage. Monthly exhaustion affects availability without inventing a monthly pacing window.
- Release microphone tracks after the last dictation lease ends, including when capture acquisition races with cancellation.
- Keep the scrollbar at the edge of fullscreen panes.
- Expand the default preview pool from `41000–41009` to `41000–41999` in Kintsugi’s installer and generated Caddy configuration. Preserve existing and retired origin assignments; do not recycle origins or change hostnames.
- Expand saved legacy ten-port defaults during installer updates, preserve custom ranges, and allow explicit expansion without changing saved image sources, pins or admin settings. Reject shrinking an existing pool.
- Contain pane-loading and live-subscription failures within the affected pane, with a retry action, so sibling panes remain usable.

Thanks to Larry Hudson for the classifier credentials, OpenCode Go usage and microphone-release contributions.

## Existing installations

An app-only update cannot expand an installation’s saved proxy range or rewrite an external Caddyfile. Existing proxy installations need the updated installer and matching Caddy configuration; see [the proxy recovery instructions](https://github.com/rcarmo/kintsugi/blob/v0.3.0/docs/automation.md). Ensure Caddy’s open-file limit accommodates the larger listener pool and confirm its reload succeeds. The expanded pool supports 1,000 retained or retired origins and remains finite.

System capability and app policy-reader format remain 2; the app minimum remains 0. Custom repositories, private registry access, explicit pins, network protections and retained-pair downgrade safeguards are unchanged.

Stop active code-mode scripts before downgrading to an app that predates code mode. Image rollback preserves journals; it does not restore old session data or make old task registries understand new executable tasks.

## Verification and limits

The pre-release local full suite passed 2,217 tests, with 39 skips and zero failures. Lint/types, frozen dependency installs, System bundling and workflow validation passed. Generated full-range Caddy configuration passed validation with Caddy. Manual browser review confirmed that a failed preview left the agent pane usable. Capacity tests cover retained and retired origins and expansion after restart; no installed host was changed by those checks.

The six-scenario, no-inference Chrome layout subset passed all 89 checks again before tagging. It excludes sending, busy states, long transcripts and iOS keyboard behaviour.

Physical microphone and permission-prompt behaviour, live classifier/image providers, iOS keyboard/rotation, complete connected-model composer acceptance, and a complete installed update/rollback cycle have not been verified for this release. Earlier recorded-audio acceptance covers only its documented scenario.

Kintsugi retains its four semantic APT layers. The evaluated six-layer balancing proposal was not adopted.

Tagged GitHub Actions verifies native AMD64/ARM64 images and the candidate app/System pair before publishing app, System and workspace versions and advancing `latest`. `stable` stays unchanged. Publication does not restart installations.
