# v0.3.3

This patch adds workspace Properties, finite resource budgets and OOM containment, fixes stopped/hung-workspace home-page loading and the Linux updater boot race, and bounds Changes reads before allocation. It incorporates 17 reviewed upstream commits through `6f7351bf`.

## Resource protection and Properties

- Give System finite RAM, swap, CPU and PID defaults. Account for other services already using host memory and leave management/build headroom when admitting workspace allocations. Establish a durable runtime boundary when an older installer supplied none.
- Preserve finite manual Docker limits during installer replacement and rollback. Installations with manually applied caps should run this release’s host installer once: an older installed updater may still invoke its older installer for the first replacement. Saved release sources and pins remain authoritative. See [resource protection and upgrade guidance](https://github.com/rcarmo/kintsugi/blob/v0.3.3/docs/automation.md#workspace-properties-and-resource-protection).
- Apply per-workspace limits, account for child OOM events and stop automatic restart loops. Persist parked intent and failure/cooldown state across service/container recreation. Explicit unpark after the cooldown acknowledges a retry; deliberately stopped workspaces stay stopped.
- Open Properties from the gear beside any workspace, including a stopped one. Show usage and peaks, desired/Docker/effective cgroup limits, OOM/exit/restart history, installation capacity and other allocations, network policy, addresses and ports. Omit container environment variables and command arguments.
- Change finite RAM, additional swap and CPU limits live, without restarting the workspace. Require acknowledgement for a dangerous RAM reduction. Preserve desired settings on an apply failure and show them separately from actual settings; do not silently retry running containers.
- Stage workspace network changes until park/unpark. Separately confirm installation-wide LAN CIDR, DNS-forwarder and search-domain edits. Preserve Off/LAN/private/listed-host modes, management/peer exclusions, DNS pinning and exact-host controls.
- Expose resource JSON reads/writes through the admin API’s `security` scope. Keep the Properties HTML outside that API.

Resource caps contain Kintsugi allocations; they do not reserve RAM against unrelated unlimited host services growing later. Lowering a live RAM limit can kill workspace processes.

## Recovery and bounded reads

- Load `/`, Settings and the workspace shell without waiting for container-backed presentation. Bound live workspace loading, contain pane errors locally and allow force parking to bypass hung adapters. Inspecting a stopped workspace does not start it.
- Install the updater-owned early tmpfiles rule at updater startup, including when an older installer copied the new updater. Keep directory ownership/mode repairs idempotent.
- Bound Changes descriptor, blob, process-output, batch and snapshot reads before allocation. Sparse 12 GiB regressions cover oversized working-tree and repository inputs. The focused upstream PR is [#64](https://github.com/lucasmeijer/AgentsInTheCloud/pull/64).

## Upstream adaptations

- Add `.proto` highlighting and visual-pane scrolling/popover fixes.
- Contain egress stream errors and retain Tailscale DNS exceptions needed by build clients.
- Load native Agent history lazily, prioritise the visible workspace, avoid redundant live-region snapshots and compile native-history validators.
- Read one workspace’s template when preparing an Agent prompt, recover from stale Agent references, and prevent Browser navigation from accumulating address bars.
- Catch up Agent visibility after a lazy mount so the Agent subscribes after its parent selection settles.

Untrusted visual iframe messages remain limited to scrolling; they cannot replay host management shortcuts.

## Compatibility

System capability is **3**; the default app minimum remains **0**. Properties/resource controls require System 3. The network-policy reader format remains **2**.

Configured inspector allocations introduce independent resource-policy reader version **1**. App-only preparation/activation, paired update planning/rollback and the installer refuse resource-unaware images when saved allocations require support. Missing labels mean reader zero. Image rollback preserves settings; it does not restore older configuration. Custom repositories, registries, credentials, explicit pins and retained-pair rollback remain supported.

Native IPv4/IPv6 nftables forwarding, atomic replacement and rollback probes passed. Tagged image jobs run the resource probe on AMD64 and ARM64.
