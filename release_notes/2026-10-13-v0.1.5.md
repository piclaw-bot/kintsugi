# v0.1.5

This patch brings selected upstream fixes into Kintsugi and preserves the fork's networking, installer, custom release sources and usage-rendering changes.

## Agents and tools

- Upgrade the Pi stack to 1.2.0 and use Codex Sol's 500k context default. Explicit model overrides still win.
- Preserve tool cancellation notes without a local Pi Durable patch.
- Stop sending Codex subagent output schemas, which could break later requests after plain-text tool errors.
- Let prompt templates take precedence over same-named Claude Code commands.
- Expose repository skills to Claude Code and load project instructions consistently for terminal agents. Both `.agents-in-the-cloud/AGENTS.md` and `.kintsugi/AGENTS.md` are supported.

## Workspace and interface fixes

- Disable the EROFS overlay mount index and pin the matching runtime. This fixes workspace startup failures on kernels that default OverlayFS indexing to on.
- Keep disk diagnostics available on Btrfs, including filesystems without a fixed inode limit.
- Suggest allowed hosts for recognised secret names while retaining manually entered choices.
- Add a remembered wrapping toggle to the Files display menu. Wrapping stays on by default.
- Show agent names on narrow screens and retain comparison details on wider screens.

## Usage and publishing

- Read Copilot usage from the configured GitHub Enterprise issuer. Token and issuer are read together; concurrent requests cannot cross issuers. Kintsugi's allowance counters, quota selection and pacing fixes remain in place.
- Share default publishing destinations across build, release and update code. Saved custom repositories, private registry access and version pins retain precedence.
- Stop CI on ordinary coordination pushes. Relevant pull requests, explicit manual checks and version-tag releases still run checks.

The final pre-release local suite passed 2,084 tests with 39 skips and zero failures. Lint, TypeScript and workflow validation passed. File wrapping and the compact picker were reviewed manually in the browser.

Tagged publication verifies the exact source revision and native AMD64/ARM64 images before publishing the app, System and workspace versions and advancing `latest`. `stable` is unchanged. Publication does not restart existing installations.
